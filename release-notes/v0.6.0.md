Agent Console 0.6.0 shows the app version in the header and makes **Send to Host** reliable. The host checks now give true results, and the dialog tells you why a send is blocked.

## Downloads

| File | System | What it is |
|---|---|---|
| `agent-console_0.6.0_amd64.deb` | Debian, Ubuntu (x64) | The CLI and the desktop app. Install with `sudo apt install ./agent-console_0.6.0_amd64.deb`. |

## New

- **App version in the header.** The header shows the version, for example `v0.6.0`. When a window shows an older page than the server, the label shows "reload for v…". Click it to reload the page.

## Fixes

- **A second send works.** Each send makes a new branch on the host from the sent commit: the branch name, else `<name>-<host>`, else `-2`, `-3`. A branch on the host is never moved or used again.
- **Send of a repo with no remote.** The bundle is fetched with no target branch. The host no longer refuses it when its repo has `main` checked out.
- **Send with 0 commits ahead.** The console no longer makes an empty bundle, which git refuses.
- **The dialog says why a send is blocked.** A missing repo, and failed ssh, tmux, tunnel or agent checks, block the send. The reason shows above the button and as its tooltip. The login, sleep and repo folder checks only warn.
- **Warnings look like warnings.** A warning shows `!`. Before, it showed a green tick in the dialog and in the Hosts panel.
- **Tunnel check.** A `401` or `403` answer from the console means that the tunnel works. The health route needs the token, so a working tunnel was reported as failed.
- **Login check.** The check no longer says "not logged in" when `claude` is not found. On macOS, the hint tells you that the login is in the Keychain, which an SSH login cannot read. Use `claude setup-token` and set `CLAUDE_CODE_OAUTH_TOKEN` in `~/.zshenv` on the Mac.
- **PATH hint.** The hint names `$HOME/.local/bin` of the native Claude installer, and `/opt/homebrew/bin` for Homebrew.
- **Repo folders with `~/`.** The repo folder check expands `~/`. Before, an existing folder such as `~/code` was reported as "Folder not found".
- **Hosts panel.** An open card of a connected host no longer says "Not connected".

## Known limits

- The desktop app is not signed. On macOS, after you copy it to Applications, run `xattr -dr com.apple.quarantine "/Applications/Agent Console.app"` one time. On Windows, SmartScreen can show a warning: click **More info**, then **Run anyway**.
- On macOS, an SSH login cannot read the Keychain. A worker on a Mac host needs `CLAUDE_CODE_OAUTH_TOKEN`, or a Keychain that you unlocked in the tmux server of the host.
- 0.5.2 and 0.5.3 had no public release. Their fixes are in this list.
